# 星瑞 GKUI E01 / Android 5.1 本地适配

目标为用户确认的 2020 款星瑞旗舰、GKUI、亿咖通 E01（MT6735）、Android 5.1。原厂蓝牙电话和音乐可用；独立诊断没有获得标准 Android 蓝牙适配器；系统设置蓝牙开启后立即关闭。不要把这些症状直接解释为蓝牙硬件故障。

本工作目录基于 carlito12345/DiPlay，移入旧安卓兼容代码，最低版本 API 22。它与此前 DiPlay-Geely-Android43 的 0.2.10 测试包是两个源码目录。当前版本为 0.2.11-e01-android51-test，包名 com.shihab.diplay.e01legacy。

## 本次修复

- 合并后的音频通道枚举、重复生命周期、媒体回调和报告导出接口错误。
- 音频焦点在 API 22–25 使用旧调用，保留吉利焦点优先级与过期回调检查。
- AudioTrack 使用 API 21 构造方式；API 22 使用旧阻塞写入方法。低版本缺少的音频统计不能作为实测结果。
- API 22 更换视频 Surface 时重建解码器；使用兼容的并发映射和原子计数更新。
- 系统服务、权限、HUD 尺寸读取、方向盘广播注册、Unicode 文件名处理补旧版本路径。
- 兼容旧版 AndroidX 的诊断导出测试，并显式清除 Robolectric 测试间的 FileProvider 静态路径缓存；生产路径隔离保持原逻辑。

## 验证边界

2026-10-05 同步候选的 common/shared 回归报告 1,075 项通过，另有诊断工具 6 项通过，无失败、错误或跳过。另执行 NewApi 专项 lint；这是 Android API 静态扫描，不是全项目所有 lint 检查。Robolectric 4.17 不提供 API 22 运行环境；新增 API 22 分支测试在 API 23 沙箱内模拟执行。构建和静态测试不能证明 E01 的 ARM 音视频、USB 或无线实车可用。

## 蓝牙尚未解决的部分

两个原仓库的无线通路均调用标准 Android RFCOMM。现有 H52 ANW/ECarX 检测来自其他固件，不能当作 E01 已验证协议。不能仅因为厂商电话/音乐可用就假定有第三方可访问的 iAP2 双向数据通道。

旁边 outputs 目录的 DiPlay-E01-Bluetooth-Diagnostics-v02.apk 新增“识别 E01 原厂蓝牙应用（无需电脑）”：读取固件标识、名称匹配的系统应用包名/版本/APK 路径，以及相关 framework 文件名。用户可拍照传回结果。名称匹配可能漏掉接口；此功能不读私有数据、不尝试未知 Binder 事务、不启动厂商服务、不修改开关。诊断工具原有 RFCOMM 测试和开启请求仍是独立按钮，识别原厂应用无需点击它们。

下一步依据实车识别结果定位对应 APK/JAR，再核实数据连接、读写、关闭和权限协议；未经验证不宣称无线修复。

## 电脑连接条件

Android 5.1 标准 ADB 需要开发者选项中的 USB 调试及支持设备模式的调试口。尚未确认本车开放哪个入口或端口，不能让用户盲接 USB-A 对 USB-A 线。Android 11 的扫码配对流程不适用于本车。

若固件明确提供网络 ADB，可让电脑和车机连接同一网络，使用其显示的地址和端口执行 adb connect；不要假定 5555 一定开放。标准旧安卓无线 ADB 流程通常先要有可用的 USB ADB 连接，再启用 TCP 模式。当前没有本车 ADB 连接，优先采用上述无需电脑的识别工具。

参考：[Android ADB 官方文档](https://developer.android.com/tools/adb)。
